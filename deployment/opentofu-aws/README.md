# byrle on AWS, with OpenTofu

The release image on ECS Fargate, RDS for Postgres, and an Application Load Balancer on TLS
with an ACM certificate. [runbook](../../docs/runbook.md) says what to run in what order once
it is up. `make opentofu-check` runs `tofu fmt -check` and `tofu validate`. Nothing here has
been planned or applied against an AWS account yet.

It needs OpenTofu 1.13 or later. `make opentofu-check` runs 1.13.9.

| Piece | Where |
|---|---|
| a VPC | two public subnets, for the load balancer and the tasks, and two private ones, for RDS and EFS |
| the load balancer | `proxy_url`'s name, on 443 from `allowed_cidrs`. It passes plain HTTP to nginx |
| the proxy's task | one Fargate task: `config` writes the policy and nginx's server block and exits, then nginx on port 80 and `byrle daemon` at `127.0.0.1:8080` |
| the refresh task | `byrle refresh` alone, started by EventBridge Scheduler on `refresh_schedule` |
| Postgres | RDS, `byrle` database and user, reached with `sslmode=require` |
| the spool | the task's own storage, up to 8 GiB of its 30 |
| audit and account event logs | EFS, at `/var/log/byrle` in the task |
| the database password and `BYRLE_RP_KEY` | Secrets Manager. Generated by the apply and kept out of the state |
| the containers' output | CloudWatch Logs, `/ecs/<name>` |

The tasks have public addresses, for their requests to the registries. Their security group
admits only the load balancer.

## 1. Configure

```
cp terraform.tfvars.example terraform.tfvars
```

| Variable | Default | Set to |
|---|---|---|
| `region` | none, required | the AWS region |
| `byrle_image` | none, required | the release by digest, `ghcr.io/krishardy/byrle:<version>@sha256:<digest>`, after `gh attestation verify oci://<image> --repo krishardy/byrle` |
| `proxy_url` | none, required | the load balancer's address as installing machines reach it. Lockfiles record it |
| `certificate_arn` | none, required | an ACM certificate for `proxy_url`'s name, in `region` |
| `allowed_cidrs` | none, required | the addresses of the machines that install through byrle |
| `route53_zone_id` | `""` | a hosted zone, to add `proxy_url`'s name as an alias of the load balancer |
| `mode` | `observe` | `""` to enforce |
| `github_token_secret_arn` | `""` | a Secrets Manager secret holding a token, for GitHub's Advisory Database |
| `environment` | `{}` | any other setting `byrle --help` lists, as `NAME = "value"` |
| `policy_file` | `policy.yaml` | another policy file in this directory |
| `architecture` | `ARM64` | `X86_64` |
| `db_instance_class`, `db_multi_az` | `db.t4g.small`, `false` | a larger instance, a standby |
| `deletion_protection` | `true` | `false` before `destroy` |

Configure a backend for the state before the first apply. The state holds no password or key.

## 2. Apply

```
tofu init
tofu apply
eval "$(tofu output -raw refresh_now)"
curl https://byrle.example.com/-/byrle/ready
```

`init` checks the providers against `.terraform.lock.hcl`.

byrle applies its migrations at startup. `/-/byrle/ready` answers 200 once the first refresh
has loaded intel. Until then, an artifact answers 503.

## 3. Accounts and tokens

The image has no shell. ECS Exec runs byrle in the running task, with its environment:

```
task=$(aws ecs list-tasks --cluster byrle --service-name byrle --query 'taskArns[0]' --output text)
aws ecs execute-command --cluster byrle --task "$task" --container byrle --interactive \
    --command "byrle account create alice"
```

It needs the Session Manager plugin for the AWS CLI.

## 4. Change it

| Change | Then |
|---|---|
| `policy.yaml`, a variable, a new release | `tofu apply`. A new task starts once the old one has stopped, so installs go unanswered for about a minute |
| a new database password | raise `db_password_version`, `tofu apply`, then `aws ecs update-service --cluster byrle --service byrle --force-new-deployment` |
| a new `BYRLE_RP_KEY` | raise `rp_key_version`, `tofu apply`, then the same `update-service` |
| a new nginx | set the digest in `ecs.tf`. `make check-deps` reports a tag that moved |

One task runs at a time, because two would append to the same logs on EFS.

## 5. Watch it

| What | How |
|---|---|
| byrle's and nginx's output | `aws logs tail /ecs/byrle --follow` |
| the last refresh | the `byrle/byrle/<task>` stream of the latest refresh task, in the same group |
| ready | `curl https://<name>/-/byrle/ready` |
